# DECISIONS.md — RosterBay decision log

Format: `## YYYY-MM-DD` heading per day; one `- **topic** — decision. *Why:* reason.` bullet per decision. Newest day first.

## 2026-07-29 — Inline data marks (phase 2 follow-on)

- **`components/data-marks.tsx` is the row-scale sibling of `stat-spark.tsx`** — deviation bar, week strip, load bar, attendance bar. *Why a shared module and not four inline SVGs:* the compliance spark proved the pattern works, and the next four places that wanted it would otherwise each have invented their own scale, grace threshold and colour rule.
- **Hue encodes magnitude past grace, never direction.** The deviation bar initially rendered "short" teal and "over" amber. *Why changed:* that asserts under-delivering a client's booked hours is the good outcome. Which side of the centre line the bar sits on already carries direction; colour is free to carry severity instead.
- **Grace-aware colouring, reusing `LATE_THRESHOLD_MIN`.** The first render turned a 2-minute clock-in amber. *Why it matters:* by the third row amber means nothing, and the whole point of the mark is that an actually-late row leaps out. The marks now share the flag engine's own threshold rather than inventing a second one.
- **Load bars scale to the cohort peak, not to an invented cap.** *Why:* the schema has no contracted-hours or availability model, so "4 of 6 shifts" would be asserting a business rule that doesn't exist. Relative load is a fact; capacity would be a guess.
- **The site card takes one added query (`useShiftsRange`), knowingly.** *Why:* it's the same week key the roster already caches, so it's normally a cache hit, and a site directory that can't say which sites are short this week is a list of addresses rather than an ops screen. This is the only place in either phase where a screen gained a data dependency for presentation's sake.
- **An unfilled shift outranks a filled one on the same day in the site strip.** *Why:* the gap is the thing worth surfacing; showing the day as covered because *something* is covered would hide exactly what the strip exists to show.
- **`AttendanceBar` ticks rather than reading `Date.now()` in render.** React Compiler flagged the impure call. *Why the fix is a tick and not a suppression:* an in-progress shift's bar runs to the present moment, so reading the clock during render meant it froze at whatever unrelated re-render happened last. Ticking makes the live bar grow as the shift runs, which is what the screen was already implying.

## 2026-07-29 — Visual transformation phase 2 (the signature layer) — admin only

- **`acstTimestamp()` was producing wrong timestamps outside Adelaide — fixed.** `new TZDate('2026-07-29T00:00:00', ACST)` parses the bare string in the **system** timezone and only then re-expresses it in ACST, so on a browser at UTC+5:30 it returned 04:00 ACST instead of 00:00. Every shift created or retimed through the UI was offset by the gap between the operator's timezone and Adelaide's. Now built from numeric parts via `TZDate.tz`. *Why it survived this long:* seeded shifts are written in SQL, so the demo data was always right and only interactive creates were wrong. **This is a data-logic change in a phase that declared none** — I am naming it rather than burying it: CLAUDE.md calls the half-hour offset a deliberate domain-knowledge signal, and the module I was building sat directly on top of the broken primitive.
- **A day is not 1440 minutes.** South Australia observes DST, so the October and April transition days are 23 and 25 hours. `dayWindow()` measures the real length of each ACST day and every position is a fraction of *that*. Two tests pin it. *Why:* assuming 1440 shifts every bar on the two days a year when a scheduler is least forgiven for being wrong. A related trap: `addDays` on an instant adds 24 hours, which on the fall-back day lands at 23:00 the *same* date and made the window measure zero — the next date is now derived by pure calendar arithmetic.
- **Behaviour preserved by construction, not by re-implementation** — the day view's bars register the *same* `useDroppable({ id: shift.id, data: { shift } })` the week chips did. *Why:* the droppable was already per-shift rather than per-cell, so drag-to-assign, the live eligibility ring, the conflict dialog and broadcast all work through the new surface with zero changes to `checkAssignment()` or the page's drag handlers. The 23 conflict-engine tests pass unmodified, which is the evidence.
- **Coverage intensity is relative to the day's own peak, not an absolute headcount** — *Why:* an absolute ramp renders a quiet Sunday as uniformly empty and hides the one gap in it. The question the ribbon answers is "where is *this* day thin", not "how does today compare to Tuesday".
- **Unfilled state carries texture, not just colour** — a drawn SVG hatch on bars and coverage cells. *Why:* red-versus-green is exactly the channel a colour-blind ops manager cannot use, and this is the one status where being missed has an operational cost. Texture is the redundant channel.
- **Handovers share a lane; only true overlaps stack** — a shift ending exactly where the next begins doesn't force a second lane. *Why:* back-to-back cover is the normal case at these sites, and stacking it would double every row height for no information.
- **SVG defs live in the app shell, not the roster** — *Why:* a `url(#…)` reference only resolves if the definition is in the document doing the painting. Roster-scoped defs made the compliance runway's expired hatch silently render as flat fill, which no type or test could catch.
- **The runway's past region is compressed, not proportional** — *Why:* six days lapsed and sixty days lapsed both need to read as "over the line". A proportional past axis would either push a long-lapsed cert off-screen or squash the twelve months that actually matter into a sliver.
- **Edge-drag resize is DEFERRED, not shipped.** The brief flagged it as a stretch item with permission to defer and log. *Why:* it would need pointer capture on a bar that is already a dnd-kit droppable and a click target, and the failure mode — starting a resize when the user meant to assign a worker, or vice versa — corrupts the primary interaction the whole phase promised to preserve. Times remain editable through the existing dialog, which is also the keyboard-accessible path the brief required as a fallback. **Ghost-bar create with 30-minute snapping did ship.**
- **View preference persists in localStorage via `usePersistentState`** — for view/zoom only. *Why:* anything the server owns belongs in TanStack Query; this hook exists so that boundary stays visible.
- **`tsc --noEmit` checks nothing in this repo.** The root `tsconfig.json` is a project-references stub with `"files": []`, so only `tsc -b` (what `npm run build` runs) actually type-checks. *Why record it:* a "typecheck clean" signal from `npm run typecheck` is meaningless here, and I shipped code past it during this phase before noticing.
- **`qlmanage` renders SVG onto a square canvas.** The OG generator composes on 1200×1200, centres the design, and centre-crops with `sips -c`. Also: `clipPath` coordinates resolve in the *referencing element's* user space, so a clip used inside a translated group must not repeat the translation — doing so pushed the framed screenshot entirely out of view.
- **The reference deck's 3D truck and compass are deliberately not imitated.** *Why:* they carry no data. The Cargo Layout panel is the part worth borrowing — position on a drawn object encoding real state — and the roster time grid is that idea applied to time.

## 2026-07-29 — Visual transformation phase 1 (the system) — admin only

- **Scope narrowed to `admin/` on request** — the brief's §1.3 "mobile receives the identical token set" and the matching checklist item are **not done**. *Why:* the user scoped this pass to the admin console mid-flight. The two apps are therefore now deliberately divergent: admin runs the cool layered near-blacks below, mobile keeps its warm-Stone inversion from 2026-07-14. That is a known debt, not an oversight — porting the ladder to `mobile/global.css` + `lib/colors.ts` + `lib/theme.ts` is the first task of any mobile phase.
- **Dark mode did not previously exist on web** — `ThemeProvider` has been stamping `.dark` on `<html>` since Phase 1 with **no `.dark` token block anywhere in `index.css`**, so the class landed on nothing and the toggle silently did nothing. *Why record it:* it means "add dark mode" was a build, not a retune, and it explains why nobody had reported it broken.
- **No animation library** — the brief said to use Framer Motion "already a dependency"; it is not installed (neither `framer-motion` nor `motion`). Motion is CSS: tokens + keyframes + a `.stagger` variant in `index.css`, with `lib/motion.ts` for the JS-driven cases. *Why:* fadeUp/stagger/shimmer/pulse are four keyframes, and `tw-animate-css` is already a dependency. It also means `prefers-reduced-motion` is honoured in one media query instead of per-component — the count-up is the only opt-out written by hand, because JS interpolates that value and no stylesheet can reach it.
- **Radius ladder 8/12/16 supersedes "10px everywhere"** — CLAUDE.md §6 declares one radius; the brief declares three. The brief wins as the active phase prompt. Added a fourth step, `--radius-xs` (6px), for elements under ~24px. *Why:* 8px on a 20px icon button reads as a circle, so keycaps, badges and small icon buttons needed a step below the control radius or they'd have been ad-hoc arbitrary values again.
- **Inter replaces Plus Jakarta Sans; JetBrains Mono added** — the remote Google-Fonts `@import` at the top of `index.css` is gone. *Why:* it was render-blocking on a third-party host, and both CLAUDE.md and the brief specify Inter, which was already installed and self-hosted but overridden. Mono is mandatory for every numeral, time, duration, distance, count, code and ID via the `.num` utility — the single highest-signal typographic change in the pass.
- **shadcn tokens are aliases, never independent values** — `--card`, `--popover`, `--muted`, `--border` etc. all resolve to the surface/border/text ladder. *Why:* two parallel colour systems drift within one session. This way every installed primitive inherits the ladder for free and a token change can't leave one component behind.
- **Avatar identity tones moved into tokens and re-hued** — eight `--avatar-N-bg/fg` pairs with a designed value per theme, replacing eight hardcoded light-only hexes. Dropped the slate/steel/denim/mauve members. *Why:* they were blues and purples in a one-accent system, and being light-only meant every avatar stayed a pale chip on near-black. They encode identity rather than status, which is why they're allowed to exist at all — so they stay in the warm-neutral/sage/teal family where none can be mistaken for semantic green/amber/red.
- **Leaflet vector colours come from CSS classes, not path options** — `GEOFENCE_PATH_OPTIONS` and `DISTANCE_LINE_PATH_OPTIONS` carry a `className`; the hue lives in `index.css`. *Why:* Leaflet writes path options to SVG **presentation attributes**, which do not resolve `var()`. A token could never have reached the stroke through `color:`, which is why those two hexes survived every previous pass.
- **`detectRetina` is off; `@2x` is baked into the tile URL** — CartoDB serves high-DPI tiles, and Leaflet's `detectRetina` assumes the opposite: it fakes them by incrementing `zoomOffset` and halving `tileSize`. *Why record it:* combining the two shifted the zoom math and pushed every marker off-screen — a bug with no type error, no console error and no failing test, found only by looking at the dashboard.
- **Active nav is `accent-muted`, not `surface-2`** — the brief specifies a surface-2 fill. *Why the deviation:* in light mode the sidebar sits on surface-1 (`#FFF`) and surface-2 is `#FAFAF9` — a 2% step that left the current route effectively unmarked. The accent tint reads in both themes and pairs with the accent bar and the tinted icon. The theme toggle has the same shape of problem and is solved the same way (track drops to `bg-base`).
- **`EmptyState` glyphs are hand-drawn SVG** — six line-art marks in the component, not an illustration dependency. *Why:* they inherit `currentColor` so dark mode is free, a stroked outline reads as "nothing here yet" where a filled icon reads as a button, and six of them are smaller than any package that would supply them. The old Phosphor-icon prop is kept so un-migrated call sites don't break.
- **Two deliberate non-token values remain, both documented at the call site** — the phone chassis radii and shell in `worker-frame-page.tsx`. *Why:* that is a device silhouette, not a UI surface; its dimensions are physical and a handset does not turn white in light mode.
- **Sortable table headers carry `label-micro` on the `<button>`, not just the `<th>`** — *Why:* a button does not inherit the header's micro-label treatment, so sortable columns rendered sentence-case next to uppercase non-sortable ones. Visible only in the running app.

## 2026-07-28 — Task management & shift verification (proof-of-work loop)

- **Templates are snapshotted in the app, not by a trigger** — `createShift()` copies the site checklist through the pure `instantiateShiftTasks()` (title and `requires_photo` carried by value; `template_id` kept only as provenance). *Why:* a DB trigger would be atomic but would duplicate the rule in SQL and in the unit tests the prompt requires, and drift between the two is worse than the narrow window where a shift insert succeeds and its task insert fails. Admin is the only runtime path that creates shifts; the seed does the same copy set-based in SQL because it bypasses the app entirely.
- **Clock-in no longer materialises tasks** — the old mobile "copy templates on first clock-in" block is deleted. *Why:* it was the last live-link: a shift created weeks ago would silently pick up *today's* templates the moment the worker clocked on, which is exactly what spec §1 rule 1 forbids. `useSiteTemplates` went with it — the worker app now reads templates nowhere.
- **Shift popover → EntityDrawer** — the roster's shift detail (which was already a centred `Dialog`, not a popover) is now the shared right drawer, and `EntityDrawer`'s `tabs` became optional so a single-column entity doesn't have to fake a one-tab bar. *Why:* header + worker row + progress ring + editable checklist + photo strip + issues + footer runs to roughly double the ~420px the prompt set as the promotion threshold. The drawer already owns scroll, sticky footer and the dirty-close guard.
- **`incomplete_tasks` is a flag, not a status** — it joins `effective_flags` in `time_entries_with_status` (same read-time pattern as `missing_clock_out`) but deliberately does **not** flip `effective_status` to `flagged`. *Why:* the prompt wants a real review signal that never blocks approval. As a flag it shows in the Flags column (amber, not red), explains itself in the expand, and drops the entry out of "Approve N clean" — so Marcus has to look at it — while Approve stays enabled. As a status it would have masqueraded as an attendance failure.
- **`reset_demo()` is a two-step, by rename** — 0009 renames the 0005 function to `reset_demo_base` and defines `reset_demo()` as base + `seed_proof_of_work()`. *Why:* the alternative was `create or replace` with a 400-line copy of the base seed, leaving two definitions in `setup.sql` and a dead one in 0005 for a future edit to land in by mistake. The rename is guarded so re-running 0009 is a no-op.
- **Seeded photos are storage paths, not URLs** — seeded rows store `seed/…jpg`; `proofPhotoUrl()` (mirrored both apps) passes absolute worker-upload URLs through untouched and resolves paths against the project URL. *Why:* `reset_demo()` runs nightly from pg_cron with no knowledge of the project URL, and hardcoding one into a committed migration would make `setup.sql` project-specific.
- **Seed images are generated and committed with their generator** — `scripts/make-seed-photos.mjs` builds six defocused-photo JPEGs (SVG → `qlmanage` → `sips`, the same dependency-free pipeline as the OG image); `seed-auth.ts` uploads them before calling `reset_demo()`. *Why:* "no broken thumbnails, ever" needs real objects in the bucket, and committing binaries without their source makes them unmaintainable. 72 KB for all six.
- **Acknowledge is the only admin write on an issue** — no reply, no note-back, no thread; the worker sees `Awaiting review` → `Acknowledged`. *Why:* anything richer is chat (spec §10 kill list). The status flip alone closes the loop back to the field.
- **Skipped the optional 5th stat segment** — "Open issues" is not on the dashboard strip. *Why:* every other segment navigates somewhere honest; open issues have no list page, and inventing one is scope. The red "Issue reported" attention row already carries the signal and deep-links to the shift.
- **Three bugs the running app surfaced, not the type checker** — (1) Supabase preloads `pg_safeupdate` for API roles, so `seed_proof_of_work()`'s table-wide `DELETE`s failed over RPC while passing on local Postgres; now `truncate`, as the base seed already did. (2) `FullscreenMapWrapper`'s controls (`z-index: 1000`) punched through any modal opened over a map — the photo lightbox was the first one — fixed with `isolate` on the wrapper rather than escalating the dialog's z-index. (3) A long issue note in a `colSpan` cell stretched every timesheet column, because auto table layout sizes to content; the panel now sits in a `w-0 min-w-full` wrapper and the issue row wraps to two lines. *Why record these:* all three are invisible to typecheck, build and unit tests, and two of them only reproduce against real Supabase.
- **Unknown flag values are skipped, not fatal** — `FLAG_META` / `FLAG_ICON` lookups tolerate a flag the client doesn't know. *Why:* deploying the migration before the client (the order DEPLOY.md prescribes) briefly serves `incomplete_tasks` to an older bundle, which crashed the Timesheets page outright — verified by running the pre-pass build against the migrated database.
- **Deep links for cross-page rows** — `/app/roster?shift=<id>` opens the shift sheet (with a single-shift fetch fallback when the id is outside the loaded week) and `/app/timesheets?entry=<id>` lands with that row expanded. *Why:* the dashboard's new attention rows are only useful if they arrive at the evidence; both follow the existing `?site=` / `?open=` convention.

## 2026-07-15 — Mobile reference-conformance pass (borderless soft-depth)

- **Theme-toggle crash — final fix (reload, don't live-swap)** — `NativeWind`'s `setColorScheme` force-re-renders the whole css-interop tree; under expo-router that detaches live screens from their navigation container → `NavigationStateContext.getKey()` throws "Couldn't find a navigation context." Removing `freezeOnBlur`, flattening providers, and keeping `<Stack>` a stable child all *reduced* but did not eliminate it — the forced global re-render still hit navigator internals. **Resolution: never call `setColorScheme` in a live session.** `setMode` persists the choice (awaited) and reloads the JS (`DevSettings.reload()` in dev/Expo Go, `location.reload()` on web); `useHydrateThemeMode` applies the stored scheme once **while the navigator is gated out of the tree** (`NavThemeWrapper` renders a blank View until `ready`), so the applying `setColorScheme` runs before any screen mounts. Trade-off: the toggle triggers a ~½s reload instead of an instant swap — accepted as the only crash-proof option. Guardrails that still hold: no `freezeOnBlur`; `<Stack>` stays a stable child; bottom sheets are inline absolute-fill overlays (never RN `<Modal>` / out-of-navigator Portal).

- **Borderless soft-depth in both modes** — dropped the spec §6 "1px borders separate" rule for **card surfaces** on mobile: cards now group by fill contrast + shadow (light: white card on deepened `#FAFAF9`; dark: lifted `#231F1B` card on deepened `#120F0D` canvas). Deliberate override of a CLAUDE.md "law," **authorised by the user** to match the reference apps in `ui_references/` (all borderless/soft-depth). *Kept* as borders: single-side **dividers** (footer/section/pinned-bar separators — §3.4 allows hairline dividers), form **inputs**, **button** outlines, and the **Badge/StatusPill** pill outline. Web admin is untouched — this is a mobile-only divergence.
- **Un-nested the in-shift card** — task rows and Report-issue were bordered `bg-card` boxes inside a padded `Card` (the exact double-padding anti-pattern in `issue_with_card_nesting…`). Now one card depth: borderless tonal rows. The shared `Card` primitive is consequently unused by any screen (left in place, not deleted).
- **Empty states are onboarding** — one shared `EmptyState` (large tinted glyph + bold headline + teaching copy + optional down-arrow action cue, per §3.8) replaces the thin dashed-box empties across Today/Schedule/Offers/Wallet/notifications. Wallet's points at the pinned Add button. Fixed a real bug: Today's no-shift state was rendering `ScreenPlaceholder`, whose copy says "Coming in this demo… ships in a later phase" — wrong for an empty Today.
- **Floating on-canvas headers** — shift-detail, notifications, and add-document drop the stock react-navigation header for a `ScreenHeader` with a circular back button on the background (reference: `single_screen_single_action_example`).
- **Not done (by decision):** gesture/motion craft (long-press context menus, drag-to-dismiss with background scale) — deferred to a later pass; needs `react-native-gesture-handler`.

## 2026-07-14 — Mobile UI pass (dark mode + instant clock + Today/Schedule)

- **Instant clock in/out** — `useClockIn`/`useClockOut` are now optimistic: `onMutate` flips the shift to `in_progress`/writes a synthetic entry (server-identical flags via `computeClockInFlags`) into the cache on tap, so the screen becomes the in-shift view immediately; rollback on error, `onSettled` invalidate reconciles. *Why:* the multi-step clock-in write (orphan cleanup → insert → shift update → template copy) took 5–10s; the worker must never wait on the server to feel clocked in.
- **Dark mode** — added `.dark:root` warm-Stone token block in `global.css` + `NAV_THEME.dark`; preference persisted via `expo-secure-store` in `lib/theme-mode.tsx` (hydrated before first paint to avoid a theme flash), toggled from the account sheet. - **Today as hub** — greeting header (time-of-day + first name), hero next-shift card, one prominent Clock In/Out pinned to the thumb zone with success/impact haptics (`expo-haptics`, guarded off web) and pull-to-refresh. *Why:* guide §3.1/§3.5 — one unmissable primary action; hub is the only multi-purpose screen.
- **Scope of this pass** — Today, Schedule, header, tab bar, and the shared placeholder/demo-banner are fully dark-ready; Offers/Wallet/notifications/shift-detail adapt automatically for className tokens but still carry a few hardcoded icon hexes (next pass). *Why:* user scoped "today and schedule first."

## 2026-07-11 — Phase 3 (Offers, Dashboard, Landing, Ship)

- **Offer resolution in a trigger** — a security-definer trigger on accepted `offer_responses` marks the offer filled, assigns the shift, and writes winner + admin notifications. *Why:* workers can't (and shouldn't) update unassigned shifts through RLS, and doing it client-side would leave a half-resolved offer if the winner disconnected mid-sequence; the partial unique index remains the sole race arbiter, so the trigger only ever runs in the winning transaction.
- **Activity feed has no events table** — derived client-side from the already-live time-entry, offer, and notification streams (the prompt's preferred path). Session-scoped items animate in when their timestamp postdates page mount.
- **Eligibility = engine verdict ≠ block** — role match + cert compliance + no overlap; a 38h *warning* does not exclude a worker from a broadcast (accepting overtime is the worker's call, consistent with the roster's assign-anyway).
- **"Others viewing" is real** — Supabase presence on an `offers-presence` channel, not a faked number; shows only when > 0.
- **OG image** — generated at build-prep time from an SVG via macOS `qlmanage`/`sips` into `admin/public/og.png` (1200×630); no runtime dependency. Regenerate by editing the SVG in the repo history if branding changes.
- **Keep-alive treats any HTTP response < 500 as alive** — anon REST hits an RLS-guarded table; an empty 200 or a 4xx still proves the project is unpaused.
- **Dark mode skipped** — the token architecture makes it *possible* but re-tinting six semantic colors + leaflet tiles + OG assets is not under the prompt's ~1h bar; light mode is canonical per spec §6.

## 2026-07-11 — Phase 2 (Roster, Timesheets, Today, Realtime)

- **Override convention** — cert-compliance overrides store the reason in `shifts.notes` prefixed `OVERRIDE: ` (per the phase prompt) *and* in the Phase-1 `override_reason/by/at` columns. The notes prefix is what the UI renders (amber note on the shift detail); the columns are the audit trail. Double-booking has no override path anywhere.
- **missing_clock_out at read time** — `time_entries_with_status` view (0006) computes it (no clock-out 2 h past shift end) plus `effective_flags`/`effective_status`; late/out_of_zone are stored at clock-in mutation time by the shared `compliance.ts` module (mirrored both apps, like database.types).
